01 / MOTIVATION

The Research Problem

LLM inference is increasingly deployed in production, yet performance at the stage level is poorly understood. We identified three core challenges:

🧠 Memory Bandwidth Wall

Autoregressive decode reads the entire model from DRAM for each token. GPU tensor cores sit 98% idle during decode — waiting on memory.

Arithmetic Intensity: 1 FLOP/byte
A100 Ridge Point: 208 FLOP/byte
Gap: 208×

📊 Profiler Accuracy

GPU profilers add 27–39% overhead, distorting the metrics they measure. Which profiler gives trustworthy numbers?

Kineto: +38.9% overhead
Nsys: +26.8% overhead

🔍 Abstraction Gap

Production frameworks (vLLM) hide the inference pipeline. Can't tell if the bottleneck is prefill, decode, attention, or MLP.

Need stage-level visibility without sacrificing production relevance.

Why Nsys Wins on Overhead

  • Intercepts at CUDA driver level (fewer hooks)
  • No Python-level instrumentation
  • External process — doesn't share GIL

Why Kineto Is Still Useful

  • Maps Python ops → CUDA kernels (stack traces)
  • Built into PyTorch — no external tools
  • Better for debugging specific operators

Key Insight: GEMM Dominates at 90.4%

Matrix multiplications in QKV projections and MLP layers consume 9 out of every 10 GPU cycles. Since GEMMs during decode are memory-bandwidth bound (reading weights from DRAM), quantizing weights from 16-bit → 4-bit directly reduces the dominant bottleneck.

Why Quantization Helps

Since decode time = weight_bytes / bandwidth, reducing weight precision directly increases throughput:

BF16
15.2 GB → 42 tok/s
INT8
7.6 GB → ~60 tok/s
INT4
3.8 GB → ~80 tok/s

Expected real-world: INT8 ~1.3-1.5×, INT4 ~1.7-2× speedup. Lower than theoretical due to dequantization overhead.

Key Scaling Findings

  • Decode scales worse than linear — 1.94× params → 1.74× slowdown (bandwidth-bound)
  • Prefill scales better — 1.94× params → only 1.63× slowdown (compute-bound)
  • KV cache grows 6.75× — wider hidden dims + more layers
  • P99 variance doubles at 14B — memory pressure effects

09 / NEXT STEPS

Quantization Study

Reducing the memory bandwidth bottleneck

AWQ (INT4)

Activation-aware weight quantization. Pre-quantized models available. Best speed/quality tradeoff.

~4 GB for 7B model
Expected: ~1.7× speedup

GPTQ (INT4)

Hessian-based weight optimization. Widely available. Slightly lower quality.

~4 GB for 7B model
Expected: ~1.5× speedup

BitsAndBytes (INT4/8)

On-the-fly quantization. No pre-quantized model needed. Runtime dequant overhead.

~4 GB / ~8 GB
Expected: ~1.3-1.5× speedup

Research Questions for Quantization Phase

  • Does INT4 achieve the expected 1.7–2× decode speedup on A100?
  • How does quantization affect the prefill vs decode balance?
  • What is the accuracy-speed tradeoff: perplexity impact vs throughput gain?
  • Which quantization method (AWQ vs GPTQ vs BNB) performs best on our pipeline?
